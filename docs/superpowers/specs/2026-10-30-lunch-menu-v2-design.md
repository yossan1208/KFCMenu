# ver2.0: ランチ／通常メニューの切り替え 設計書

- 作成: 2026-10-30
- ステータス: ユーザー確認待ち
- 前提: `docs/superpowers/specs/2026-09-05-kfc-menu-optimizer-design.md`（元の設計書）、`docs/superpowers/specs/2026-10-24-set-recommendation-design.md`（おすすめの設計書）

## 背景・目的

KFCのメニューに次の変更があった。

- 一部の値上げ
- ランチ時間とそれ以外で、注文できるセットと値段が違う
- 実際に使ってみると、メニュー名の略称（コンビ、チキビス、2セットなど）がわかりにくかった

`KFCメニュー.numbers` に正確なメニュー名と新しい値段を書き直した（2026-10-26）。これを反映し、画面でランチと通常を切り替えて計算できるようにする。

## ユーザーが決めたこと

- メニューデータは numbers の名前・値段どおりにする。中身（何が入っているか）は今までと同じ
- ランチ時間は毎日 10:00〜15:00（10:00 以上 15:00 未満）。曜日は関係ない
- 計算ボタンの下に「ランチ／通常」の切り替えを置く。画面を開いたときはスマホの時刻で自動的に決め、手で切り替えもできる
- 切り替えたら、表示中の結果は消す（もう一度「計算」を押す）
- バーガーコンビとチキン&ビスケットセットは、ランチ時間外は注文できない
- キッズメニューは時間帯によらず同じ
- 画面にバージョンは表示しない。git に `v1.0`（今の版）と `v2.0`（今回の版）のタグを付ける
- データの持ち方は「購入選択肢ごとに、注文できる時間帯を持たせる」（案1）

## データの持ち方

購入選択肢に、省略できる `availability` を追加する。

- `"lunch"`: ランチ時間だけ注文できる
- `"regular"`: ランチ時間外だけ注文できる
- 省略: いつでも注文できる
- それ以外の値: menu.json の書き間違いとして、読み込み時にエラーにする（画面には「メニューを読み込めませんでした」と表示される）

同じ中身のランチ版と通常版は別々の購入選択肢として持つ。`id` は別にし（例: `burger_set_lunch` と `burger_set_regular`）、`name` は同じでよい。

## 計算ロジック（KfcMenu.Core）

- `MenuOption` に `Availability`（文字列、省略可）を追加する
- 時間帯を表す `ServiceTime`（`Lunch` / `Regular`）を追加する
- 時刻から時間帯を決める関数を追加する: 10:00 以上 15:00 未満なら `Lunch`、それ以外は `Regular`
- 時間帯で購入選択肢を絞る関数を追加する: `Availability` が省略か、その時間帯と一致するものだけを返す
- `MenuParser` で `availability` の値を確認し、`lunch` / `regular` / 省略 以外ならエラーにする
- 最安（`CheapestComboFinder`）、展開（`VariantExpander`）、おすすめ（`SetRecommender`）は変えない。絞り込んだ購入選択肢を渡すだけ

## 画面（Home.razor）

- 「計算」ボタンのすぐ下に、2択の切り替えを置く: 「ランチ（10:00〜15:00）」「通常」。選ばれている方がわかる見た目にする
- 画面を開いたとき、スマホの現在時刻（ブラウザのローカル時刻）で初期値を決める
- 切り替えたら、表示中の結果・おすすめ・入力エラーを消す。必要数の入力はそのまま残す
- 計算では、選ばれている時間帯で絞った購入選択肢から、最安とおすすめを求める
- 計算中（「計算中...」表示中）は切り替えも押せないようにする
- 結果の表示形式は今と同じ（購入選択肢の名前が numbers の正式名になる）

## テスト

- 時間帯の判定: 9:59 → 通常、10:00 → ランチ、14:59 → ランチ、15:00 → 通常、0:00 → 通常
- 絞り込み: ランチは30件、通常は28件。ランチにバーガーコンビとチキン&ビスケットセットが含まれ、通常には含まれない。通常のバーガーセットは890円
- `MenuParser`: `availability` の不正な値でエラーになる。省略した購入選択肢は `Availability` が null
- 既存のテスト（最安・展開・おすすめ）は、本物の menu.json を読むので値段の変更で期待値が変わる。ランチ時間の表で計算し直し、通常時間の表でも代表的な注文の期待値を追加する。期待値は、全部調べる確認用スクリプトで出す
- 画面は、公開用ビルドをサブパスで配信し、ヘッドレスChromeで確認する（切り替え、初期値、切り替えで結果が消えること、ランチと通常で値段が変わること）
