# 必要数の＋−ボタン 設計書

- 作成: 2026-11-19
- ステータス: 確認待ち
- 前提: `docs/superpowers/specs/2026-10-30-lunch-menu-v2-design.md`（ver2.0 の設計書）

## 背景・目的

スマホで使うと、必要数を入れるたびに数字キーボードを出して打つ必要があり手間がかかる。商品ごとに「＋」「−」で1ずつ増減できるようにする。

PCのブラウザでは数字の入力欄に上下の矢印（スピンボタン）が出るので、ボタンは要らない。スマホではこの矢印が出ないので、ボタンが要る。

## ユーザーが決めたこと

- 入力欄は残し、その左右に「−」「＋」を置く。数字は今までどおり直接入力もできる
- 押すたびに1ずつ増減する
- PCではボタンを出さない。スマホでだけ出す
- 長押しで連続して増やす機能は入れない

## 方式（検討した案）

| 案 | 内容 | 採否 |
|---|---|---|
| 入力欄＋左右のボタン | 入力欄はそのまま、左右に−と＋ | 採用（ユーザーが選択） |
| ボタンだけ | 入力欄をなくし、数字は表示だけ | 不採用: チキン12本のような大きな数を入れるのが大変 |
| 長押しで連続増減 | 押し続けると数が増え続ける | 不採用: 作りが複雑になる。必要数はふだん数個 |

## 振る舞い

- 「−」を押すと必要数が1減る。「＋」を押すと1増える。結果は0〜99に収める（範囲外の数が入っているときに押すと、近い端の値になる。例: 150で−を押すと99）
- 必要数が0のとき「−」、99以上のとき「＋」は押せない
- 計算中（「計算中...」表示中）は押せない。計算ボタン・時間帯の切り替えと同じ
- 数を変えても、表示中の結果は消さない。数字を直接入力したときと同じ
- ボタンには読み上げ用の名前を付ける（例: 「チキンを1つ減らす」「チキンを1つ増やす」）

## ボタンを出す条件（Claude の判断。変えたい場合は指摘してください）

画面の幅ではなく、「指で操作する端末かどうか」で決める: CSS の `@media (hover: none) and (pointer: coarse)` のときだけボタンを出し、それ以外（マウスのPC）では隠す。

- 理由: ボタンが要るのは「入力欄に上下の矢印が出ない」端末で、それはスマホ・タブレットなど指で操作する端末。幅で決めると、PCでウィンドウを狭くしたときにも（矢印が出ているのに）ボタンが出てしまい、逆にタブレットでは（矢印が出ないのに）ボタンが出ない
- スマホは必ずこの条件に当てはまるので、「スマホでだけ出す」は満たす。タブレットでも出る点が「スマホサイズで」と違う

## 見た目

```
チキン          [ − ]  2  [ + ]
骨なしチキン    [ − ]  0  [ + ]
```

- ボタンは指で押しやすい大きさ（44px 四方程度）
- スマホ幅（375px）で、商品名・ボタン・入力欄が1行に収まる
- PCの見た目は今と同じ

## 構成

- 変更: `KfcMenu.Web/Pages/Home.razor`（ボタンと増減の処理）、`KfcMenu.Web/wwwroot/css/app.css`（ボタンの見た目と出す条件）
- 変更しない: 計算ロジック（`KfcMenu.Core`）、menu.json

## テスト

- 計算ロジックは変えないので、既存の自動テスト（61件）がそのまま通ること
- 画面はブラウザで確認する
  - スマホ（指で操作する端末として表示）: ボタンが出る、＋−で増減する、0で−・99で＋が押せない、直接入力もできる、計算結果が正しい、375px幅で1行に収まる
  - PC: ボタンが出ず、今と同じ見た目
